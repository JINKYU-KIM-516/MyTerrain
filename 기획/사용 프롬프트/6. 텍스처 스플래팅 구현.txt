텍스처 스플래팅이란
지형 전체에 텍스처 하나만 입히면 평지도 절벽도 같은 재질로 보인다. 스플래팅은 여러 장의 디퓨즈 텍스처(잔디·바위·모래·눈 등)를 준비해두고, 픽셀마다 "이 위치엔 어떤 재질이 얼마나 섞여야 하는가"를 나타내는 가중치(weight)로 블렌딩하는 기법이다. 가중치를 어디서 얻느냐로 두 갈래로 나뉜다.

텍스처 기반(control map): 아티스트가 그린 splat map(RGBA 채널 하나당 재질 하나) 텍스처를 따로 두고 그걸 샘플링해서 가중치로 쓴다. Unity 지형 시스템이 이 방식이다.
절차적(procedural) — 이번에 물어본 방식: 별도 텍스처 없이, 정점의 높이와 경사도라는 이미 갖고 있는 값에서 가중치를 계산한다. 3번 높이맵 기법에서 HeightMap::Evaluate가 뽑아주는 정규화된 높이, 그리고 지형 생성 때 이미 계산해둔 법선(경사도)을 그대로 재사용할 수 있어서 리소스가 하나도 늘지 않는다는 게 장점이다.
높이 기반 블렌딩
정규화된 높이(0~1, Params::amplitude 기준)를 구간별로 나눠 재질을 배정한다. 예를 들어:

높이 구간	재질
0.0 ~ 0.2	모래
0.2 ~ 0.5	잔디
0.5 ~ 0.8	바위
0.8 ~ 1.0	눈
문제는 경계에서 딱 잘라버리면 재질이 뚝 끊긴 선으로 보인다는 것이다. 그래서 step 대신 smoothstep으로 전이 구간을 두고 두 재질을 선형 보간한다.

hlsl
float wSand  = 1 - smoothstep(0.15, 0.25, h);
float wGrass = smoothstep(0.15, 0.25, h) * (1 - smoothstep(0.45, 0.55, h));
float wRock  = smoothstep(0.45, 0.55, h) * (1 - smoothstep(0.75, 0.85, h));
float wSnow  = smoothstep(0.75, 0.85, h);
경사도 기반 블렌딩
경사도는 법선과 up 벡터의 내적으로 얻는다. dot(normal, float3(0,1,0))이 1이면 완전 평지, 0에 가까우면 수직에 가까운 절벽이다. 1번 기법에서 GridMesh::Generate가 이미 이웃 높이의 중앙 차분으로 법선을 계산해서 넘겨주므로, 스플래팅에서 새로 계산할 게 없다 — 법선을 그대로 재활용하면 된다(높이맵 기법에서 언급된 "이웃 텍셀 차분으로 경사도를 얻는다"가 바로 이 계산이다).

hlsl
float slope = 1 - saturate(dot(normal, float3(0,1,0))); // 0=평지, 1=수직
float wCliff = smoothstep(0.3, 0.6, slope);
실전에서는 "경사가 급하면 잔디가 안 붙고 바위가 드러난다"는 규칙이 훨씬 중요하다. 그래서 보통 높이 기반 가중치를 먼저 계산한 뒤, 경사도로 잔디/모래 계열을 깎아 바위 쪽으로 밀어준다:

hlsl
// 경사가 급해질수록 잔디 가중치를 바위로 이전
float toRock = wCliff * (wSand + wGrass);
wSand  *= (1 - wCliff);
wGrass *= (1 - wCliff);
wRock  += toRock;
이렇게 하면 "낮고 평평한 곳은 모래, 낮아도 경사가 급하면 바위, 높아도 완만하면 눈 덮인 평원, 높고 급하면 암벽" 같은 자연스러운 조합이 나온다.

왜 "정점" 기반인가 — 계산 위치의 트레이드오프
가중치 계산을 **정점 셰이더(VS)**에서 할지 **픽셀 셰이더(PS)**에서 할지가 갈린다.

VS에서 계산: 정점마다 가중치 4개를 계산해서 보간기(rasterizer)로 픽셀까지 흘려보낸다. PS는 텍스처 4장 샘플 + 가중합만 하면 되니 훨씬 싸다. 단점은 분할 수가 낮으면 경사/높이 전이가 삼각형 사이에서 선형 보간되어 뭉개진다 — 3번 높이맵 기법에서 이미 겪은 "텍셀보다 정점이 성기면 디테일이 뭉개진다"는 문제와 정확히 같은 성격이다.
PS에서 계산: 픽셀마다 월드 높이(VS에서 world Y를 그대로 보간해 넘기면 됨)와 보간된 법선으로 가중치를 다시 계산한다. 훨씬 정밀하지만 픽셀당 연산이 늘어난다.
지금 아키텍처는 BasicTerrain.hlsl이 이미 VS에서 world position과 normal을 PS로 넘기고 있으므로, 추가 데이터 없이 PS에서 계산하는 쪽이 자연스럽다. 정점 밀도가 이미 충분히 촘촘한 지형(3번 높이맵처럼 분할 수를 텍셀 밀도에 맞춰 올린 경우)이라면 VS 계산으로 내려서 비용을 아껴도 차이가 거의 안 보인다 — 이건 지형 예제로 두 방식을 토글해서 비교해보기 좋은 지점이다.

통합 시 필요한 변경 (기존 구조 기준)
셰이더 리소스: 재질별 디퓨즈 텍스처(모래/잔디/바위/눈) + 샘플러 4벌 추가. HeightMapTexture처럼 별도 SRV 슬롯에 바인딩.
상수 버퍼: 높이/경사 임계값(전이 구간 시작·끝)을 파라미터화하려면 CBTerrain에 float4 하나 정도 추가 필요 — 3번에서 192바이트가 됐던 것처럼 16의 배수를 유지해야 한다.
HLSL 확장: gHeightMapParams.z(고도 색상 모드)처럼 스플래팅도 모드 플래그로 켜고 끄게 해서 1~3번 경로에 영향 없게 분리하는 패턴을 그대로 따르면 된다.
타일링 아티팩트: 텍스처를 월드 좌표에 그대로 매핑하면 넓은 지형에서 반복 패턴이 도드라진다. UV에 타일링 배율(예: worldPos.xz * 0.1)을 곱해 쓰거나, 절벽처럼 경사가 급한 곳은 수직 방향 UV가 늘어나 보이므로 필요하면 트라이플래너 매핑까지 갈 수 있다 — 다만 이건 4번 범위를 넘는 다음 단계 개선점이다.
