#질문
펄린 노이즈 지형 설명


#답장
프로젝트 문서(기본-평면-그리드-구조.md)와 GridMesh.h를 보니 이미 HeightFunc 훅이 준비돼 있어서, 2번 기법은 그 함수 안에 무엇을 넣느냐가 전부입니다. 그 "무엇"을 설명드릴게요.

1. 왜 그냥 rand()가 아닌가

height = rand() 로 하면 정점마다 값이 독립적이라 백색 잡음(가시밭) 이 나옵니다. 지형은 인접한 두 점의 높이가 비슷해야 하고, 동시에 패턴이 반복돼 보이지 않아야 합니다. 노이즈 함수는 이 두 조건을 만족하는 "연속적인 난수 필드" 입니다.

핵심 성질 세 가지:

결정적(deterministic) — 같은 (x, z) 를 넣으면 언제나 같은 값. 그래서 청크를 나눠 만들어도 경계가 이어지고(10번 무한 청크), 저장할 필요가 없습니다.
연속적 — 미분 가능해서 법선이 튀지 않습니다.
대역 제한(band-limited) — 한 옥타브는 대략 한 가지 크기의 굴곡만 만듭니다. 그래서 여러 옥타브를 겹치는 게 의미가 있습니다.
2. 펄린 노이즈 자체 (Ken Perlin, 1985 / improved 2002)

가상의 정수 격자를 하나 더 깝니다(지형 메시 격자와는 별개). 입력 좌표 (x, z) 에 대해:

1) 셀 찾기      xi = floor(x),  xf = x - xi        (zi, zf 도 동일)
2) 코너 4개의 gradient 벡터를 해시로 결정
                g00 = grad(perm[xi   + perm[zi  ]])
                g10 = grad(perm[xi+1 + perm[zi  ]])  ...
3) 각 코너에서 내적  n00 = dot(g00, (xf,   zf  ))
                     n10 = dot(g10, (xf-1, zf  ))  ...
4) fade 곡선으로 보간
                u = fade(xf), v = fade(zf)
                n = lerp( lerp(n00,n10,u), lerp(n01,n11,u), v )

여기서 중요한 두 가지:

gradient 를 쓴다는 점. 값 노이즈(value noise)는 코너에 스칼라 난수를 두고 보간하는데, 펄린은 코너에 방향 벡터를 두고 "그 코너에서 이쪽으로 얼마나 기울었는가"를 내적으로 계산합니다. 결과적으로 정수 격자점에서 값이 항상 0 이고, 굴곡의 마루/골이 격자점이 아니라 셀 내부에 생겨서 훨씬 자연스럽습니다. 2D 기준 gradient 는 보통 8방향(±1,0),(0,±1),(±1,±1) 중 해시로 하나를 고릅니다.

fade 함수는 반드시 6t⁵ - 15t⁴ + 10t³. 단순 선형 보간이면 셀 경계에서 기울기가 꺾여 격자 무늬가 그대로 보이고, smoothstep(3t²-2t³)은 1차 미분만 연속이라 법선(=1차 미분)에 셀 경계 줄이 남습니다. 5차 곡선은 2차 미분까지 0이라 조명이 깨끗합니다. 지형에서 이 차이는 와이어프레임보다 솔리드 셰이딩에서 훨씬 잘 보입니다.

시드는 permutation 테이블(0~255 를 섞은 배열, 512칸으로 복제)을 어떻게 섞느냐로 줍니다. 해시가 결정적이므로 시드만 바꾸면 완전히 다른 지형이 됩니다.

출력 범위는 2D에서 대략 ±0.707 (√2/2) 이지 ±1이 아닙니다. 진폭을 정확히 맞추려면 정규화가 필요합니다.

3. fBm — 실제 지형을 만드는 부분

노이즈 한 겹은 부드러운 언덕일 뿐입니다. 지형처럼 보이게 하는 건 여러 주파수를 겹치는 것(fractional Brownian motion)입니다.

cpp
float fbm(float x, float z)
{
    float sum = 0, amp = 1, freq = 1, norm = 0;
    for (int i = 0; i < octaves; ++i) {
        sum  += perlin(x * freq, z * freq) * amp;
        norm += amp;
        freq *= lacunarity;   // 주파수 배율 (보통 2.0)
        amp  *= persistence;  // 진폭 배율   (보통 0.5)
    }
    return sum / norm;        // -1 ~ 1 로 정규화
}

파라미터 감각:

파라미터	역할	조절 시
frequency (기본 스케일)	지형의 가로 크기	낮추면 대륙, 높이면 자갈밭
octaves	디테일 단계 수	4~8. 셀 크기보다 작은 굴곡은 낭비
lacunarity	옥타브마다 주파수 배율	2.0. 정확히 2면 반복감이 생겨 2.05 같은 값을 쓰기도
persistence	옥타브마다 진폭 배율	0.5. 높이면 거칠고, 낮추면 매끈
amplitude	최종 높이 배율	셀 크기 대비로 잡아야 경사가 자연스러움

옥타브 수 상한은 메시 해상도가 정합니다. 셀 크기보다 잘게 진동하는 옥타브는 정점 사이에서 잘려나가 앨리어싱만 만듭니다. 분할 수를 바꿀 때 옥타브도 같이 조절하면(octaves = log2(divisions) 근처) 깔끔합니다.

4. 변형 — 여기서 지형 "성격"이 갈립니다

같은 노이즈에 후처리만 다르게 해도 완전히 다른 지형이 나옵니다.

Ridged (능선형) n = 1 - abs(perlin) 후 제곱 → 날카로운 산맥. 산악 지형은 거의 이걸 씁니다.
Billow (구름형) n = abs(perlin) → 뭉실한 언덕/모래언덕.
Terracing (계단) floor(h * k) / k 를 원본과 섞기 → 지층/논.
Domain warping fbm(x + fbm(x,z)*w, z + fbm(x+5.2, z+1.3)*w) → 좌표 자체를 노이즈로 밀어서 강줄기처럼 휘어진 지형. 비용 대비 효과가 가장 큽니다.
높이 재매핑 최종 h 에 pow(h, 2) 나 커브 적용 → 평야는 넓게, 봉우리는 뾰족하게.
5. 이 프로젝트에 붙일 때

GridMesh::Generate 가 이미 높이 함수를 받고 법선을 중앙 차분으로 계산하므로, 기법 2는 구조적으로는

cpp
terrain->SetHeightFunction([params](float x, float z) {
    return fbm(x * params.frequency, z * params.frequency) * params.amplitude;
});

이고, 나머지 작업은 파라미터를 실행 중에 조절하고 즉시 다시 생성하는 UI/입력 쪽입니다. 주의할 점:

좌표 스케일. 셀 크기가 1이고 분할이 256이면 월드 크기가 256인데, 노이즈에 그대로 넣으면 256칸짜리 격자를 지나므로 너무 잘게 나옵니다. x * 0.01 정도로 줄여서 넣거나, "지형 전체가 노이즈 몇 칸을 덮을지"를 파라미터로 두는 게 직관적입니다.
파라미터를 바꿀 때마다 CPU에서 메시 전체 재생성. 512분할이면 26만 정점 × 옥타브 6 = 150만 번 샘플링이라 프레임이 한 번 끊깁니다. 슬라이더처럼 연속 조절하려면 (a) 조절 중엔 저해상도로 미리보기, (b) 키를 뗐을 때만 재생성, 또는 (c) 아예 정점 셰이더/컴퓨트 셰이더로 옮기는 방법이 있습니다. 7번 테셀레이션 기법으로 가면 GPU 쪽이 자연스러워집니다.
법선. 중앙 차분으로 이미 처리되지만, 노이즈는 해석적 미분(analytic derivative)도 가능합니다. 3번 높이맵까지는 차분으로 충분합니다.
축 정렬 아티팩트. 펄린은 격자 기반이라 강한 굴곡에서 수평·수직 방향 특징이 살짝 보입니다. 신경 쓰이면 좌표를 약간 회전시켜 넣거나 Simplex 노이즈로 바꿉니다(Simplex는 특허 이슈가 있었으나 2D는 만료, OpenSimplex 대안도 있음).

정리하면 펄린 = 부드러운 난수 한 겹, fBm = 그걸 여러 주파수로 겹치는 것, 지형의 개성 = 겹친 결과에 무슨 후처리를 하느냐 입니다.

이대로 2번 기법을 구현해 넣을까요? 넣는다면 조절 대상(주파수·옥타브·진폭·시드·노이즈 타입)과 재생성 타이밍을 어떻게 할지 정하고 시작하면 됩니다.

2번 펄린 노이즈 지형을 프로젝트 폴더에 바로 반영했습니다. Visual Studio에서 솔루션을 다시 열면 새 파일이 잡히고 메뉴에 2. 펄린 노이즈 지형 (Perlin Noise) 항목이 생깁니다.

지형 생성 쪽에서 실제로 새로 만든 건 노이즈 모듈 하나뿐입니다. GridMesh::Generate가 이미 높이 함수를 받게 되어 있어서, 나머지는 전부 "파라미터를 실행 중에 돌려보고 그 비용을 눈으로 보게 하는" 부분입니다.

Terrain/PerlinNoise — D3D를 전혀 모르는 순수 함수 덩어리. Evaluate(x, z, Params) 하나로 최종 높이가 나옵니다. gradient는 8방향 단위 벡터, fade는 5차 곡선(6t⁵-15t⁴+10t³), 시드는 permutation 테이블을 섞어서 줍니다. 3번 높이맵·10번 무한 청크에서 그대로 재사용됩니다.
Components/PerlinControlComponent — GridControlComponent를 상속했습니다. 분할 수·셀 크기·표시 모드는 1번 것을 그대로 쓰고 HUD만 덮어썼습니다(이 때문에 부모의 RefreshInfoText를 protected virtual로 열었습니다).
TerrainRenderer — RequestRebuild / IsMeshDirty / GetLastRebuildMilliseconds / SetCheckerScale 추가.

조작은 ↑/↓로 항목 선택, ←/→로 값 조절(누르고 있으면 연속), N 합성 방식(fBm → Ridged → Billow), M 시드 무작위, 0 기본값 복귀입니다. HUD에는 7개 파라미터와 함께 실제 나온 높이 범위, 재생성에 걸린 ms, 그리고 가장 잘은 굴곡 크기(scale / lacunarity^(octaves-1))를 띄웁니다. 마지막 값이 셀 크기의 2배보다 작아지면 "셀보다 잘아서 낭비" 경고가 붙습니다 — 옥타브를 어디까지 올리는 게 의미 있는지 바로 보입니다.

주의 하나 — Debug 빌드는 노이즈 평가가 5~10배 느립니다. 256분할·6옥타브가 Release에서 약 6ms인데 Debug에서는 수십 ms라 값을 연속으로 돌리면 뚝뚝 끊깁니다. 그래서 키 리핏 간격을 재생성 시간에 맞춰 자동으로 늘리게 해뒀지만, 파라미터를 편하게 만져보려면 Release로 돌리는 걸 권합니다.

검증은 mingw-w64로 전체 컴파일·링크, 노이즈 모듈은 별도 테스트로 값 범위(-0.993~0.995), 정수 격자점에서 정확히 0, 연속성, 시드 결정성을 확인했고 세 합성 방식을 높이맵 이미지로 뽑아 육안으로도 봤습니다. 실제 화면 출력은 Visual Studio에서 돌려보셔야 합니다 — 안 나오는 게 있으면 알려주세요. 구조 요약은 프로젝트 문서(claude/펄린-노이즈-지형-구조.md)에 남겼습니다.
